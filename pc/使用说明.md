# 吊物轨迹监测系统 · 完整使用说明

> 适用系统：Orange Pi 3B（吊钩端传感器）+ Windows PC（岸上控制端）+ Ebyte LoRa 无线电链路
> 版本：2026-08-26 · 覆盖：传感器启用 → 轨迹录制 → 无线电控制 → 数据自动回传

---

## 一、系统总览

```
┌─────────────────────────────┐        无线电 (E90-DTU LoRa, TCP 8886)        ┌──────────────────────────────┐
│   PC 岸上控制端 (本机)        │◄──────────── 控制/状态 (HOOK 协议) ──────────►│  香橙派 3B (吊钩端)            │
│                             │                                              │                              │
│  D:\Simulate\ROS2USV\dist\  │         SSH/SFTP (数据回传, 可靠通道)          │  /root/trajectory/           │
│    hang_ctrl.py  (控制 CLI)  │◄════════════════════════════════════════════►│    recorder.py   (轨迹录制)   │
│    (无线电 + SSH + SFTP)     │                                              │    radio_recorder.py (常驻守护)│
│                             │                                              │    analyze.py     (数据分析)   │
│  hangpoint\  ← 数据落盘目录   │                                              │  ├─ MPU6050 (i2c-2, 加速度/陀螺) │
└─────────────────────────────┘                                              │  └─ u-blox GPS (/dev/ttyACM0)  │
                                                                              └──────────────────────────────┘
```

**三个组成部分**：
1. **传感器层**（香橙派）：MPU6050 惯性测量 + u-blox GPS 定位 → 融合轨迹
2. **录制层**（香橙派）：`recorder.py` 实时融合录制，输出 CSV + meta.json
3. **控制层**（PC + 无线电）：`hang_ctrl.py` 经无线电指挥录制，完成后 SSH 自动拉回数据

## 二、硬件连接（吊钩端）

| 器件 | 接口 | 说明 |
|---|---|---|
| MPU6050 | 40 针排针 3/5 脚（I2C2-SDA/SCL, m1 复用） | VCC→1 脚(3.3V)，GND→6 脚，**禁止接 5V** |
| u-blox GPS | USB → `/dev/ttyACM0` | 即插即用，多星座 |
| LoRa 电台 | 网口 → 网关 `192.168.0.127:8886` | Ebyte E90-DTU(400SL30L)，TCP 透传 |

> ⚠️ **操作关键**：录制启动后**吊钩需保持静止约 10~40 秒**（IMU 校准 10s + GPS 收敛 ≤30s），否则校准数据失效。

## 三、香橙派端软件

### 3.1 轨迹录制器（已部署，勿改）

```bash
# 手动录制（一般由 PC 遥控，也可直接执行）
cd /root/trajectory
python3 recorder.py --duration 1800     # 录制 30 分钟（默认）
python3 recorder.py --duration 60       # 录制 1 分钟
```

- 输出：`/root/trajectory/runs/YYYYMMDD-HHMMSS.csv` + `.meta.json`
- 采样：IMU 50Hz，GPS 1Hz，融合后写入 28 列
- 优雅停止：Ctrl+C 或收到 SIGTERM（自动补全文件尾、写 meta.json）

### 3.2 常驻命令守护（systemd 自启）

```bash
systemctl status radio-recorder        # 查看状态（应 active）
systemctl restart radio-recorder       # 重启守护
journalctl -u radio-recorder -n 50     # 查看日志
```

- 守护连接无线电网关，监听 `HOOK` 命令（与船控 `CMD` 完全隔离）
- 收到 `HOOK REC_START` → 启动 recorder；收到 `HOOK REC_STOP` → 优雅停止
- 无 GPS 信号时回报 `REC_FAILED`（**不会**产生成功回执）

### 3.3 板上数据与分析

```bash
python3 /root/trajectory/analyze.py runs/<stem>.csv --metric report          # 统计报告
python3 /root/trajectory/analyze.py runs/<stem>.csv --metric static_drift    # 静止漂移断言
python3 /root/trajectory/analyze.py runs/<stem>.csv --metric attitude_static # 静止姿态稳定性
python3 /root/trajectory/analyze.py runs/<stem>.csv --metric swing_amplitude # 摆动幅度分析
python3 /root/trajectory/analyze.py runs/<stem>.csv --metric hoist_delta --expect_delta 5 --tolerance 1.5  # 升降位移验证
```

> `--metric` 支持 `report` / `static_drift` / `attitude_static` / `swing_amplitude` / `hoist_delta`；`hoist_delta` 需配合 `--expect_delta` 与 `--tolerance`。

### 3.4 吊物 GPS 位置上报（`gps_tcp_client.py`，POS 1Hz 错峰）

吊物端 `/home/orangepi/Desktop/radio/gps_tcp_client.py` 已按《三端无线电防冲突契约》§4 修改，把吊物实时位置以 `POS` 行经数传电台发给船与 UI，1Hz：

```bash
python3 gps_tcp_client.py --serial /dev/ttyACM0 --baud 115200 --host 192.168.0.127 --port 8886 --interval 1.0
```

- **发送节奏**：GPS 秒边界 + **0.35s 相位**（即 GPS 秒 `N.350` 发射，`--interval 1.0` 为默认），与船控 `USV`（1Hz、相位 0.0s，即 GPS 秒 `N.000`）错峰 0.35s，避免两帧 1Hz 报文同秒碰撞。
- **无 GPS 退化**：GPS 不可用（fix 过期 >2s）时退化为墙钟 + ±50ms 随机抖动（约 1Hz），命令可靠性由船侧 ACK + 重传兜底。
- 已按规范 §4 修改并实机验证：GPS 秒 N.350 相位对齐、实测间隔 0.97~1.04s（1Hz）。协议细节见 `HOOK_PROTOCOL.md` 与 `RADIO_NETWORK_SPEC.md`。

## 四、PC 端控制程序（核心交付）

### 4.1 安装与准备

```powershell
# 依赖（仅需一次）
pip install paramiko

# 可选：设置环境变量避免每次输密码
$env:HANG_PI_USER = "root"
$env:HANG_PI_PASS = "orangepi"
# 可选：覆盖 SSH 目标链（默认 FRP 主 → WLAN 备），逗号分隔依次尝试
$env:HANG_PI_SSH_TARGET = "root@139.196.232.191:6006,root@192.168.0.123:22"
```

> 说明：未安装 paramiko 时仍可运行 `--selftest` 与 `--mock-sftp`（离线测试），仅真实 SSH 拉取需要 paramiko。

运行前确认：
- ✅ 香橙派守护 active（`systemctl status radio-recorder`）
- ✅ 无线电两端电台已上电、网关 `192.168.0.127:8886` 可达
- ✅ SSH 可达（默认 FRP `139.196.232.191:6006`，备用 WLAN `192.168.0.123:22`）

### 4.2 命令速查

| 命令 | 功能 |
|---|---|
| `python hang_ctrl.py start [--duration 秒]` | 无线电发录制命令 → 等确认 → 完成后自动拉回数据（缺省 `--duration` 时发送 `HOOK REC_START`，由守护用默认 1800s） |
| `python hang_ctrl.py stop` | 提前结束录制 → 自动拉回 |
| `python hang_ctrl.py status` | 查询守护状态（`idle` / `recording` / `busy`） |
| `python hang_ctrl.py pull --stem <时间戳>` | 按指定录制拉取（如 `--stem 20260825-153000`） |
| `python hang_ctrl.py pull --latest` | 拉取最新一次完整录制 |
| `python hang_ctrl.py test` | 无线电回环自检（HOOK TEST ↔ ACK，≤60s） |
| `python hang_ctrl.py --selftest` | 离线自检（不连硬件），退出码 0 = 通过 |

### 4.3 完整操作示例

```powershell
cd D:\Simulate\ROS2USV\dist

# ① 自检（可选，确认软件就绪）
python hang_ctrl.py --selftest

# ② 无线电链路回环测试（确认电台互通）
python hang_ctrl.py test

# ③ 开始录制 5 分钟（吊钩此时应保持静止 ~10-40s）
python hang_ctrl.py start --duration 300 --user root --password orangepi
#   → 发送 HOOK REC_START 300 → 香橙派录制 → 约 5 分钟后自动拉回数据

# ④ 如需提前结束
python hang_ctrl.py stop --user root --password orangepi

# ⑤ 查看结果
dir D:\Simulate\ROS2USV\hangpoint
```

### 4.4 离线测试（无电台 / 无 SSH）

不接触硬件时验证拉取与自检逻辑：

```powershell
cd D:\Simulate\ROS2USV\dist
python hang_ctrl.py --selftest                                  # 离线自检，退出码 0 = 全部通过
python hang_ctrl.py pull --stem 20260825-153000 --mock-sftp D:\fake-pi   # 用本地伪目录验证拉取
```

- `--mock-sftp` 指向的目录下放 `runs\<stem>.csv` + `.meta.json`（或直接放目录本身），即可离线演练拉取流程，不产生任何网络连接。
- `--selftest` 不触网，覆盖消息构造/解析、stem 与 meta 校验、原子改名、不完整对拒绝等逻辑（实测 29/29 通过）。

### 4.5 常用参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--host` / `--port` | `192.168.0.127` / `8886` | 无线电网关地址 |
| `--user` / `--password` | 环境变量或 root | SSH 凭据（不硬编码） |
| `--ssh-target` | FRP → WLAN 自动切换 | `[user@]host:port`，逗号分隔多目标（同 `HANG_PI_SSH_TARGET` 环境变量） |
| `--hangpoint-dir` | `D:\Simulate\ROS2USV\hangpoint` | 本地数据落盘目录 |
| `--runs-dir` | `/root/trajectory/runs` | 香橙派运行目录（绝对路径） |
| `--mock-sftp DIR` | 无 | 本地伪 SFTP 目标（离线测试，不连真实 SSH；取 `<DIR>/runs/` 或 `<DIR>` 本身） |

## 五、数据说明

### 5.1 回传文件（`hangpoint\`）

每次录制产生一对文件，按时间命名：
```
20260825-153000.csv         # 28 列轨迹数据（约 0.7MB/分钟；30 分钟约 20MB）
20260825-153000.meta.json   # 元数据（含 origin/survey_in/零偏/校准/采样率/duration/rows/coast/zupt/stop_reason）
```

> 实测参考：`20260825-102955`（duration=1800s, rows=91169）CSV 约 19.4MB；`stop_reason` 落盘值为 `duration` 或 `signal(15)`（PC 拉取时统一规范化为 `signal`）。

### 5.2 CSV 28 列

| 类别 | 列 |
|---|---|
| 时间 | `t_mono` |
| GPS 原始 | `gps_lat, gps_lon, gps_alt, gps_fix, gps_hdop, gps_speed_ms, gps_course_deg` |
| IMU 原始 | `imu_ax..az, imu_gx..gz, imu_sat` |
| 姿态 | `att_roll, att_pitch, att_yaw` |
| 融合轨迹 | `fused_n, fused_e, fused_u, fused_vn, fused_ve, fused_vu, fused_lat, fused_lon, fused_alt` |
| 状态 | `zupt`（零速检测：`0` 非静止 / `1` 零速静止；GPS 失效 coast 的统计见 meta.json `coast` 字段） |

> 单位：加速度 m/s²，陀螺 rad/s，姿态 rad，ENU 米，速度 m/s。详见 `HOOK_PROTOCOL.md` 与板载 `CSV_SCHEMA.md`。

### 5.3 精度说明（如实）

- **相对轨迹形状**（摆动/升降）：cm~dm 级（IMU 主导）
- **绝对位置**：GPS 级（水平 1-3m，垂直 3-6m；融合垂直 ~1-2m）
- **yaw 航向**：静止/纯摆动时漂移（无磁力计）

## 六、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `REC_FAILED` | 录制时无 GPS fix（30s 超时） | 检查 GPS 天线/遮挡；`lsusb` 确认 u-blox；必要时 USB 重枚举 |
| 回环 `test` 无 ACK | 电台未上电 / 网关地址不对 | 确认电台供电；`Test-NetConnection 192.168.0.127 -Port 8886` |
| 拉取失败/超时 | SSH 不可达 | 确认 FRP/WLAN 网络；`--ssh-target` 指定可用路径 |
| `REC_BUSY` | 已有录制进行中 | 等待或先 `stop` |
| GPS 无输出 | 接收器挂起 | USB 重枚举恢复：`echo 0 > /sys/bus/usb/devices/7-1/authorized` 再 `echo 1 > /sys/bus/usb/devices/7-1/authorized` |
| 守护不在线 | 服务异常 | `systemctl restart radio-recorder`；看 journal |
| 数据不足 | 磁盘满（约 20MB/次） | `df -h /root`；清理旧 runs |

## 七、已知限制（如实）

1. **无线电为半双工**：控制命令可能延迟/重发；数据回传走 SSH（可靠），不受影响
2. **数据量**：30 分钟 ≈ 20MB/次；Pi 上原件保留（可定期清理）
3. **香橙派无 RTC**：时间靠 NTP 校时，断网时时钟可能漂移（实测曾偏差 +34s）；建议在板上配置 NTP/chrony，否则文件名时间戳可能不准
4. **GPS 偶发挂起**：USB 重枚举可恢复（见故障排查）
5. **船控隔离**：本系统使用 `HOOK` 前缀协议，与 `ui_display.py`（船控）完全独立，互不干扰
